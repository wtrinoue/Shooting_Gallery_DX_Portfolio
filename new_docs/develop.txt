■ やりたいこと (ユーザーの希望)
  - 新しい別世界モード「トワイライトゾーン」を作る。
  - 的を撃つと、視界が一気に灰色に変わる (世界が止まったように見える)。
  - その灰色の景色にひびが入り、破片になって割れ、割れた向こうの「謎の空間」へ行く。
  - (未定) 謎の空間で何を撃つか。実装の前にユーザーに確認する。→ 下の「決めること」

■ 演出の流れ (案)
  1. 的を撃つ (TWILIGHT の的。見た目は渦巻き・時計など)。
  2. 屋台の的をしまう (屋台そのものは、まだ見えたまま)。
  3. その瞬間の景色を、プレイヤーの頭の位置から 360度 1回だけ撮影する (キューブマップ)。
  4. 撮影した景色を、プレイヤーを内側から包む破片の球 (半径 2〜3m) に白黒で貼り、本物の景色と入れ替える
     → 「世界が一瞬で灰色に止まった」ように見える。ここで「キーン」という音。
  5. 球にひびの線が広がる (ピキピキッ…という音)。
  6. 破片がばらばらに回転しながら落ちる / 遠くへ飛び散る (ガシャーン)。
     破片の後ろには、もう謎の空間ができていて、割れたすき間から見えてくる。
  7. 謎の空間の中で遊ぶ (時間制)。
  8. 帰り (ユーザー希望: 割れた破片がまた張り合わさって戻る):
     a. 時間切れ。まわりから、行きに落ちていった破片が逆回しのように飛んで戻ってくる (カシャ、カシャ…と集まる音)。
        破片には行きと同じ「灰色に止まった元の世界」の景色が貼ってある。
     b. 破片が全部はまると、元の世界の灰色の球が完成する (謎の空間は見えなくなる)。
     c. ひびの線が光りながら消えていく (ふさがる)。
     d. 灰色の景色に、ゆっくり色が戻る (白黒 → カラー)。
     e. 色が戻りきった瞬間に球を消す → 本物の元の世界 (屋台の前) に戻っている。
     (予備案: 白い閃光で戻るだけ。美術館モードの帰りと同じ)

■ 技術的なやり方
  ◇ 灰色にする (後処理エフェクトは使わない)
    - URP の後処理 (Volume の彩度 -100) は、WebGL の VR (両目で2回描く) と Quest で重いので使わない。
    - Camera.RenderToCubemap で、切り替わる瞬間に1回だけ撮影する。
      ・解像度は 512 くらい (RenderTexture, dimension = Cube)。使い回す (毎回作らない。GC に注意)。
      ・撮影用のカメラを1つ用意し、プレイヤーの頭の位置に置いて撮る (メインカメラは使わない)。
      ・撮影の一瞬だけフレームが引っかかる → 撮影と同時に画面を一瞬白っぽく / 灰色にして隠す (ScreenFader)。
    - 白黒にする小さなシェーダーを1つ追加する (Unlit。キューブマップを方向でサンプルして、明るさだけにする)。
      ・破片に貼るので、各頂点の「球の中心からの向き」で cube をサンプルすれば、破片が飛んでも元の場所の景色の切れはしに見える。
        (破片が動いても絵がずれないように、元の向きを UV か頂点の色に入れておく)
      ・ひびの線を光らせる値 (_Crack 0〜1) もこのシェーダーで持つ。
    - WebGL で RenderToCubemap が使えない / 重い場合の予備案:
      撮影せず、半透明の灰色の球を重ねてから割る (見た目は少し落ちる)。

  ◇ 破片の球
    - 画面に貼る方法は VR では使えない (目の前に張りついて酔う)。必ず周りの空間に置く (頭の位置を中心に、半径 2〜3m)。
    - 頭に追従させない (世界に固定。頭を動かすと破片の見え方が変わる)。
    - 球をあらかじめ破片 (100〜200枚) に割ったメッシュを、ビルダーで作って保存する (ボロノイ風。三角形をいくつかまとめた形でもよい)。
    - 破片は1つの材質。動かす時は Transform を1枚ずつ動かすか、まとめて1つのメッシュにして頂点を動かす (軽さで決める)。
    - 割れ方: 正面 (撃った的の方) から割れ始め、外側へ広がるように少しずつ時間をずらして落とす。
      落ち方は重力 + 回転 + 外向きの速度 (Stall.FallAway と同じような計算)。

  ◇ 帰りに破片を張り合わせる
    - 行きで割った時の、破片ごとの動き (落ちた先の位置と回転) を覚えておき、その逆をたどって元の場所へ戻す。
      ・落ちた後の破片は消さずに、遠く (霧の中・空間の下) に置いておく (または、帰りの時に遠くの所から呼び戻す)。
      ・戻り方: 最初は速く、はまる直前にゆっくり (逆再生だけだと重力で加速して不自然なので、ease-out で戻す)。
      ・はまる順番: 行きと逆 (最後に落ちた破片から戻る) か、まわりから真ん中へ。最後の1枚が正面にはまると「カチッ」。
    - 貼る景色は、行きに撮ったキューブマップをそのまま使う (帰る世界と同じ景色なので、もう一度撮らなくてよい)。
      ただし屋台の並びなどが行きと変わるなら、球が全部はまって何も見えない間に、元の世界を出して撮り直してもよい
      (球が視界を全部ふさいでいる間は、後ろの世界を入れ替えても気づかれない)。
    - 色を戻す: 白黒にするシェーダーに彩度の値 (_Saturation 0〜1) を持たせ、0 → 1 にゆっくり上げる。ひびは _Crack を 1 → 0。
    - 球を消す直前に、後ろの本物の世界を元どおりに出しておく (屋台・床・ハッチ・明るさ)。
      撮った景色と本物の世界が同じ見え方なら、球を消しても切り替わりに気づかない。
      → 撮った景色と同じ位置 (頭の位置) で消すこと。プレイヤーが頭を動かしていると少しずれるので、色が戻る時に少し光らせて隠すとよい。

  ◇ 謎の空間 (案。ユーザーと相談)
    - どこまでも続く白黒の市松の床 (霧で果てが見えない)。
    - 宙に浮くドア・時計・階段・目玉・渦巻き。ゆっくり回ったり漂ったりする。
    - 灰色〜紫がかった空、霧。BGM は不気味な音 (Sfx で合成)。
    - 的の案: 宙に浮くドアが開くと中から的が出る / 時計の針を撃つ / 自分の分身 / 逆さまに落ちてくる物 など。

■ このプロジェクトのやり方に合わせること (既存のモードと同じ作り)
  - GameManager.Twilight.cs (partial) を作る: CanOfferTwilight / StartTwilight(yaw) / OnTwilightArrived / EndTwilight / OnTwilightLeft / OnTwilightClosed。
    ・参考: Core/GameManager.Museum.cs (白い閃光で行き来する、いちばん新しいモード)。
  - Modes/Twilight/TwilightZone.cs: 演出と空間の出し入れ。イベント Arrived / Left(bool) / Closed、duration、CloseTime、TimeLeft、Begin(yaw, delay)、End(immediate)。
  - Builder/Modes/GalleryBuilder.Twilight.cs: 破片の球のメッシュ・謎の空間・的の見た目 (TwilightLook)。
  - TargetKind に Twilight (行く的) と、空間の中の的の種類を足す (enum の末尾に足す。途中に入れるとシーンの値がずれる)。
  - 追加しないといけない所 (美術館モードを足した時と同じ):
    ・GameManager.cs: フィールド (twilightZone, 色), TwilightActive, ChallengeActive, DebugKinds, イベント登録, 時間切れ, HUD, StopEverything, OnTargetHit の case
    ・GameManager.ModeQueue.cs: IsModeKind / EndAllForNewMode / StartPendingMode
    ・GameManager.WorldGate.cs: GateWorlds に足す (今 14 個。屋台 6軒 × 3 = 18 個まで入る)
    ・Targets/WeaponDropper.cs: StageOffer (twilightOffer)・Offers・StageKinds・LifetimeOf・CanOfferStage・PointsOf・青い玉の条件
    ・Builder/GalleryBuilder.WeaponDropper.cs: looks の一覧と WeaponLook の分岐
    ・Builder/GalleryBuilder.cs: BuildTwilight() と gm.twilightZone
  - 屋台・床・ハッチの片付け: 始まってすぐ HideHatch / SetFlatFloor、屋台は Sink。帰りは RiseStallsAfter などで戻す。
  - 音は Core/Sfx.cs で合成する (キーン・ピキピキ・ガシャーン・不気味な BGM)。
  - GC に注意: 毎フレームの new をしない。使い回す List、FxPool、PointText.Of を使う。
  - 重さ: 動かない部品は MeshMerger.Merge でまとめる (ArtMuseum.Awake と同じ)。WebGL の VR は両目で2回描く。
  - 完成したらシーンを「シーンに生成」で作り直す必要がある。

■ 決めること (実装の前にユーザーに聞く)
  1. 謎の空間で何をするか (的の種類・遊び方)。
  2. 帰り方: 破片が集まって張り合わさって戻る (ユーザー希望。上の「帰りに破片を張り合わせる」) で決まり。細かい戻り方 (順番・速さ) は試して調整。
  3. 割れ方: 落ちる / 外へ飛び散る / 吸い込まれる。
  4. 灰色は完全な白黒か、少し色を残す (セピア・青み) か。
  5. 長さ (秒)。ほかのモードは 45〜52 秒くらい。

■ 試す時に見ること
  - VR で酔わないか (破片が世界に固定されているか)。
  - 撮影の瞬間の引っかかりが目立たないか (エディター / Quest / unityroom の WebGL)。
  - WebGL で RenderToCubemap が動くか。動かなければ予備案へ。
  - 破片が多すぎて重くないか (枚数を調整)。
